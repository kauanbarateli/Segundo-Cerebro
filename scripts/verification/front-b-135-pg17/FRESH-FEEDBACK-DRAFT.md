# Feedback instalação nova — ensaio descartável

O caso `fresh-feedback` usa um container PostgreSQL 17.11 isolado, com catálogo, roles, Auth, sessão, moderação e event-store sintéticos. O SQL original guardado é fixado por hash; as duas guardas fatais só são retiradas da cópia em memória usada naquele container. A fixture reproduz a constraint cuja definição e expressão foram informadas pelo operador e exige o hash de definição exato antes de testar. O preflight integral também exige o hash de expressão e os atributos fixados; uma discrepância falha o caso, não é substituída automaticamente por outra condição. Nada acessa QA/produção.

Após a instalação em transação revertida, o caso compara ausência das tabelas e wrapper e hash da constraint. Depois instala com commit e verifica replay idempotente, rejeição de payload conflitante, isolamento de listagem por duas contas, recusa de sessão cruzada, cancelamento que bloqueia submit posterior, dois tombstones, um evento e ACL negativa para anon/authenticated. Confirmação de cleanup do executor é separada da lógica do cenário. Credenciais e dados usados são fictícios.

Não reproduz corpos e ACL reais de `require_actor` e `append_event`, Supabase Auth/PostgREST, ledger ou transporte MCP, migração hospedada, concorrência verdadeira, sessão revogada após início, retenção/remoção de tombstones, rollback depois de commit, carga de `domain_events`, nem efeitos externos. Não é validação de produção e não autoriza remover guardas, aplicar migration ou ativar flags. Os testes locais Node apenas validam preparação/pins; um run PG17 do GitHub ainda precisa ser realizado e verificado.
