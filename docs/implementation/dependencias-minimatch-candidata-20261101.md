# Candidata de compatibilidade de minimatch

O advisory GHSA-g3hv-75wg-m249 informa correção a partir de `minimatch` 11.0.1. Consumidores de lint do projeto usam versões anteriores e alguns esperam uma função como exportação principal. A candidata usa um adaptador local explícito para fornecer essa interface, delegando o cálculo ao pacote oficial `minimatch@11.0.3`, fixado pelo alias `minimatch-actual` e pela integridade do lock. O override atinge somente dependências solicitadas em versões anteriores a 11.0.1; `glob@14` continua usando o pacote oficial diretamente. Não altera os arquivos do pacote oficial nem desliga o `npm audit`.

`install-links=true` faz o npm instalar uma cópia do adaptador em vez de depender de links ou junctions. Como pacotes locais `file:` não têm integridade própria no lock, um teste compara os três arquivos instalados com os arquivos versionados e verifica o nome, a origem, a versão e a integridade do motor oficial. Um controle negativo isolado substituiu o motor por 10.2.6 e confirmou que o npm audit ainda reporta o advisory; isso não é aceite para usar essa versão.

Em Windows e Node 24, uma instalação limpa com `npm ci --ignore-scripts` passou sem link simbólico. A comparação de 3.526 caminhos existentes, 15 padrões de lint e variantes de separador e opção `dot` produziu 211.560 combinações sem diferenças. A saída de lint para 100 arquivos e três violações intencionais também coincidiu. Um corpus sintético mais amplo encontrou diferenças em classes POSIX, escapes e caminhos com `..`; a compatibilidade não é universal e novas regras ou padrões devem ser revisados. O lint completo, testes e build/PWA no CI do SHA candidato são necessários antes de aceitar a mudança.
